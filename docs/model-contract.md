# контракт backend ↔ модель

## кто за что отвечает

| модель (t1) | backend |
|---|---|
| находит события и их время | превращает события в вердикт по порогу `confidence` |
| пишет `observation`, то есть что видно в кадре | берёт название типа, правило и источник из `rules.json` (t2) по `type_id` |
| даёт боксы на ключевых кадрах | сам вырезает jpeg по `t_sec`, кодирует в base64, рисует боксы в ui |
| не пишет ссылки на нормативы | собирает итоговый json по схеме тз |

модель не придумывает ссылки на нормативы. ссылка всегда берётся из каталога t2.

## вызов

```python
def analyze(path: str, budget_sec: float | None = None) -> dict: ...
def load() -> None: ...  # необязательная, вызывается один раз при старте процесса детектора
```

то же самое через cli, чтобы t1 мог тестировать без backend:

```bash
python -m app.detector_vlm assets/videos/X-1.mov > out.json
```

- `budget_sec`: сколько секунд осталось до дедлайна задания за вычетом 15 с на сборку ответа. не больше 270 с. детектор должен уложиться: при малом бюджете он берёт кадры реже и пропускает дорогие шаги. backend передаёт `budget_sec`, только если он есть в сигнатуре.
- если модель не справилась, она бросает исключение. наружу job отдаётся как `done` с одним нарушением «Требуется ручная проверка» и кодом причины в `error`.
- после загрузки весов интернет не нужен.

## выход модели

```json
{
  "events": [
    {
      "type_id": "cash_unattended",
      "closest_type_id": null,
      "t_start_sec": 21.4,
      "t_end_sec": 23.0,
      "confidence": 0.82,
      "observation": "кассир отошёл от рабочего места, пачка купюр осталась на столе у окна клиента",
      "frames": [
        {
          "t_sec": 22.033,
          "boxes": [
            {"x": 0.31, "y": 0.52, "w": 0.12, "h": 0.08, "label": "купюры"}
          ]
        }
      ]
    }
  ]
}
```

| поле | правило |
|---|---|
| `type_id` | id из `data/rules.json`. для нарушения вне каталога `other`, тогда `observation` обязателен и конкретен |
| `closest_type_id` | только при `type_id: "other"`, иначе `null`. ближайший известный тип из `data/rules.json`, если он есть. необязательное |
| `t_start_sec`, `t_end_sec` | интервал события в секундах от начала видео |
| `frames[].t_sec` | 1–3 ключевых кадра. первый кадр это `timecode_sec` в ответе api. время берётся из pts декодированного кадра |
| `confidence` | от 0 до 1. порог выставляет backend по результатам eval, модель ничего не отсекает сама |
| `observation` | только видимое: кто, что, где. без «нарушил регламент» и без догадок о том, чего не видно |
| `boxes` | доли от 0 до 1 от ширины и высоты кадра в том виде, как его видит человек (с учётом поворота). начало координат слева сверху. боксов может не быть |
| нарушение по бездействию | `t_sec` это момент, когда шаг должен был произойти, но не произошёл. например, деньги переданы без пересчёта |

пустой `events` означает, что нарушений нет.

## нарушение вне каталога

модель не ограничена каталогом. если она видит явное нарушение кассовой дисциплины, которого нет в `data/rules.json`, она возвращает `type_id: "other"`:

```json
{
  "type_id": "other",
  "closest_type_id": "cash_to_non_client",
  "t_start_sec": 30.2,
  "t_end_sec": 33.0,
  "confidence": 0.55,
  "observation": "кассир передаёт пачку купюр через стол второму лицу в форме, клиента в кадре нет",
  "frames": [{"t_sec": 30.5, "boxes": []}]
}
```

- `observation` обязателен: кто, что, где, только видимое.
- `closest_type_id` необязателен. модель указывает его, если нарушение похоже на известный тип, но не совпадает с ним полностью.
- порог `confidence` для `other` backend держит выше, чем для типов из каталога. значение подбирается на eval.

## время: только pts, не номер кадра

видео снято с переменным fps. в датасете есть пропуски кадров, интервалы между кадрами 33 и 67 мс. поэтому `t = i / 30` даёт сдвиг. время всегда берётся из pts декодированного кадра:

```python
import av
for f in av.open(path).decode(video=0):
    t = f.time
```

backend извлекает кадр по тому же pts через тот же декодер (pyav), так что кадр совпадает с тем, что видела модель.

## что backend отдаёт наружу

```json
{
  "type": "<rules.json[type_id].name>",
  "timecode_sec": "<frames[0].t_sec>",
  "description": "<observation>. <rules.json[type_id].rule> (<документ>, <пункт>)",
  "evidence_frames": [{"timestamp_sec": "<t_sec>", "image_base64": "<чистый jpeg>"}],
  "rule": {"document": "...", "clause": "...", "url": "..."},
  "boxes": [...]
}
```

сборка `description` по `refs`:
- `doc` раскрывается через `documents[doc].title`. если `clause` равен `null`, пункт не пишется, остаётся только документ.
- для `type_id: "other"`: `<observation>. <rules.json.other.rule> (<S1 title>)`. если есть `closest_type_id`, в конец добавляется «по аналогии: <rules.json[closest].rule> (<документ>, <пункт>)».
- для `doc: "BANK"` пишется «внутренние правила банка», без пункта и ссылки.

в `evidence_frames` кадры отдаются без нарисованных боксов. как жюри оценивает кадр, мы не знаем, а разметка поверх может помешать сравнению. боксы идут отдельным полем, ui рисует их поверх кадра.
